## 한 줄 요약
컴퓨터는 **하드웨어 + 소프트웨어**로 동작하고, 사람의 의도를 기계가 실행하려면 **프로그래밍 언어 → 번역(컴파일/인터프리트) → 기계어**의 사다리를 거친다. C++가 이 사다리의 어디에 위치하는지를 잡는 장.

---

## 1.1 컴퓨터 시스템
- **하드웨어**: CPU(연산·제어), 주기억장치(RAM), 보조기억장치, 입출력장치
- **소프트웨어**: 시스템 소프트웨어(OS·컴파일러) + 응용 소프트웨어
- 폰 노이만 구조: 프로그램과 데이터가 같은 메모리에 저장 → 명령어를 순차적으로 인출·실행

## 1.2 컴퓨터 언어의 계층
1. **기계어(machine language)** — 0/1, CPU가 직접 실행. 이식성 없음
2. **어셈블리어** — 기계어에 기호(mnemonic) 부여, 어셈블러가 번역
3. **고급 언어(high-level)** — 사람 친화적, 이식성 ↑ (C++, Python …)

## 1.3 번역 방식
| 방식 | 동작 | 예 |
|---|---|---|
| 컴파일 | 소스 전체 → 목적코드 → 실행파일 | C, **C++** |
| 인터프리트 | 한 줄씩 해석·실행 | Python, JS |

C++ 빌드 파이프라인:
```
소스(.cpp) → [전처리기] → [컴파일러] → 목적파일(.o) → [링커] → 실행파일
```
- **전처리기**: `#include`, `#define` 등 지시문 처리
- **컴파일러**: 문법 검사 + 목적코드 생성
- **링커**: 여러 목적파일·라이브러리 결합

## 1.4 프로그램 개발 과정
1. 문제 분석 → 2. 알고리즘 설계(의사코드·순서도) → 3. 코딩 → 4. 컴파일/디버깅 → 5. 테스트 → 6. 유지보수

## 1.5 프로그래밍 패러다임
- **절차적(procedural)**: 함수 단위로 분해 (C 스타일)
- **객체지향(OOP)**: 데이터 + 동작을 객체로 묶음 → C++의 핵심 지향점
- 이 책은 OOP를 일찍 도입하는 접근을 택함

---

## 자주 하는 실수
- 컴파일 오류와 실행 오류(런타임)를 구분 못 함 — 전자는 빌드 단계, 후자는 실행 중
- 링커 오류(`undefined reference`)를 문법 오류로 오해 — 정의 누락/라이브러리 미연결 문제
- 인터프리터 언어 습관으로 "저장하면 바로 실행"을 기대 → C++는 컴파일 단계 필요

## 연습문제
1. 다음 오류가 컴파일 오류·링커 오류·런타임 오류 중 무엇인지 분류하라: (a) 세미콜론 누락, (b) `undefined reference to main`, (c) 0으로 나누기.
2. C++ 빌드 파이프라인의 네 단계(전처리·컴파일·링크·실행)를 순서대로 쓰고, 각 단계가 처리하는 입력과 산출물을 한 줄씩 적어라.
3. 같은 소스 파일이 컴파일 언어와 인터프리터 언어에서 실행되기까지의 차이를 2~3문장으로 설명하라.
> 힌트: 1번은 "어느 도구가 그 오류를 잡아내는가"를 떠올리면 분류가 쉽다.
