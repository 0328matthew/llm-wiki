## 한 줄 요약
Windows에서 C+어셈블리 OS를 개발하기 위한 환경을 **WSL2(Ubuntu) + QEMU + 크로스 컴파일러**로 구축한다. 핵심은 "호스트(Windows)용이 아닌, 맨바닥(bare-metal) 바이너리를 만드는 **크로스 컴파일러**"를 갖추는 것.

> 왜 크로스 컴파일러? 일반 `gcc`는 "리눅스/윈도우 위에서 도는 프로그램"을 만든다. OS는 그 밑바닥이라, OS·표준 라이브러리에 의존하지 않는 코드를 만드는 `i686-elf-gcc`가 필요하다.

---

## 0. 환경 개요
```
[Windows PC]
   └─ WSL2 (Ubuntu 24.04)        ← 코드 작성 + 컴파일
        ├─ i686-elf-gcc / nasm   ← 크로스 컴파일러 · 어셈블러
        └─ QEMU                   ← 만든 OS를 가상 부팅·테스트
```
- WSL2 자체가 경량 VM → "가상머신에서 구현" 목표와도 부합.
- QEMU는 재부팅이 1초라 OS 개발 반복 주기에 최적 (VirtualBox보다 편함).

## 1. WSL2 + Ubuntu 설치
PowerShell(관리자)에서:
```powershell
wsl --install -d Ubuntu-24.04
```
- 이미 WSL2가 켜져 있으면 배포판만 받는다.
- 설치 후 첫 실행 시 **UNIX 사용자명·비밀번호**를 직접 입력해야 한다 (이 단계는 대화형 입력 필수).
- 확인: `wsl -l -v` → Ubuntu-24.04 가 VERSION 2 로 보이면 OK.

```powershell
# 설치된 배포판/버전 확인
wsl --list --verbose
# 온라인에서 받을 수 있는 목록
wsl --list --online
```

## 2. 기본 빌드 도구 설치 (Ubuntu 안에서)
```bash
sudo apt update
sudo apt install -y build-essential bison flex libgmp3-dev libmpc-dev \
    libmpfr-dev texinfo nasm qemu-system-x86 xorriso grub-pc-bin grub-common
```
| 패키지 | 용도 |
|--------|------|
| `build-essential` | gcc·make 등 기본 빌드 도구 |
| `nasm` | 어셈블러 (부트로더/초기 코드) |
| `qemu-system-x86` | x86 가상 머신 (테스트) |
| `bison flex libgmp/mpc/mpfr texinfo` | 크로스 컴파일러 빌드 의존성 |
| `xorriso grub-pc-bin` | 부팅 ISO 이미지 생성용 (나중 단계) |

## 3. 크로스 컴파일러 만들기 (`i686-elf-gcc`)
> 가장 번거롭지만 한 번만 하면 된다. 두 갈래:

**(A) 직접 빌드** — OSDev Wiki "GCC Cross-Compiler" 정석. binutils → gcc 순서로 컴파일. 시간이 오래 걸림(20~40분).

**(B) 스크립트/사전 빌드 사용** — 처음엔 이쪽이 빠름.
```bash
# 예시: 패키지로 제공되는 경우 (배포판마다 다름)
sudo apt install -y gcc-multilib   # 32비트 타깃 보조
# 또는 커뮤니티 스크립트로 i686-elf 툴체인 빌드
```

빌드 후 PATH 등록:
```bash
echo 'export PATH="$HOME/opt/cross/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
i686-elf-gcc --version   # 동작 확인
```

## 4. 동작 확인 (Smoke Test)
```bash
nasm -v                  # 어셈블러
qemu-system-i386 --version
i686-elf-gcc --version   # 크로스 컴파일러
```
세 개가 다 버전을 뱉으면 환경 준비 끝.

## 5. 작업 폴더 & 에디터
- 코드는 WSL 홈(`~/myos/`)에 두는 게 빌드가 빠르다 (`/mnt/c/...`는 느림).
- 편집은 Windows의 **VS Code + WSL 확장**으로 WSL 폴더를 직접 열면 편하다.
- 위키 노트는 llm-wiki(Windows쪽), 실제 OS 코드는 WSL쪽 → 별개 관리.

## 잘 헷갈리는 점
- **호스트 gcc ≠ 크로스 gcc**: `apt install gcc`로 깔리는 건 리눅스용. OS 커널은 반드시 `i686-elf-gcc`로.
- `/mnt/c/`(Windows 드라이브)에서 빌드하면 디스크 I/O가 느리다 → WSL 네이티브 파일시스템(`~`) 사용.
- QEMU 명령은 타깃별로 다름: 32비트는 `qemu-system-i386`, 64비트는 `qemu-system-x86_64`.
