## 한 줄 요약
나만의 OS를 만들기 전에 알아야 할 **저수준 4대 개념** — 메모리(주소), 포인터, CPU 부팅 과정, 어셈블리 기초. C/파이썬은 알지만 하드웨어를 직접 다뤄본 적 없는 사람이 첫 "Hello World 커널"을 이해하기 위한 최소 토대.

> 목표: 거창한 설계가 아니라 **"내가 짠 코드가 부팅되어 화면에 글자를 찍는다"**를 첫 성공 기준으로 잡는다.

---

## 1. 메모리 = 번호 매겨진 사물함
RAM은 **1바이트씩 번호(주소)가 매겨진 칸의 연속**일 뿐이다.

```
주소:   0x0000  0x0001  0x0002  0x0003  ...
내용:  [  72  ][ 101  ][ 108  ][ 108  ] ...
        'H'      'e'     'l'     'l'
```

- 모든 데이터(숫자·글자·코드)는 결국 이 칸에 들어간 숫자다.
- **주소(address)** = 사물함 번호, **값(value)** = 내용물.
- 비유: 긴 선반에 부품을 칸칸이 놓고 "3번 칸 부품 가져와"처럼 *위치로* 지정.

## 2. 포인터 = 사물함 번호를 적은 메모
포인터는 **값이 아니라 "값이 있는 주소"를 담는 변수**다. ([[SA Ch09 포인터]]와 동일 개념)

```c
int x = 72;        // 어떤 칸에 72 저장
int *p = &x;       // p에는 x의 "주소"가 들어감 (&는 "주소 가져와")  예: 0x1000
int y = *p;        // *는 "그 주소로 가서 값 꺼내와" → y == 72
```

OS에서 포인터가 핵심인 이유: **특정 하드웨어 주소에 직접 값을 써야** 하기 때문.

```c
char *vga = (char*) 0xB8000;   // VGA 텍스트 화면 버퍼는 항상 이 주소
vga[0] = 'H';                  // 화면 왼쪽 위에 'H'가 찍힘!
```
> `0xB8000`은 약속된 주소. 여기에 글자를 쓰면 모니터에 바로 나타난다 — "Hello World" 커널의 핵심 원리.

## 3. CPU 부팅 과정 (x86)
전원을 켜면 내 OS가 실행되기까지의 흐름:

```
① 전원 ON
    ↓
② BIOS/UEFI 실행 (메인보드 펌웨어)
    ↓ 하드웨어 점검 후, 부팅 디스크의 첫 512바이트를 읽음
③ 부트로더 실행  ← 디스크 첫 섹터(512B), 주소 0x7c00에 적재
    ↓ 더 큰 커널을 메모리로 불러옴
④ 커널 실행  ← "내가 만든 OS"
```

핵심 포인트:
- BIOS는 **딱 512바이트**만 읽어온다 → 부트로더는 아주 작게, 보통 어셈블리로 작성.
- 512바이트의 마지막 2바이트는 반드시 `0x55 0xAA` (부팅 가능 표식)여야 BIOS가 인정.
- `0x7c00` — BIOS가 부트로더를 올려놓는 약속된 주소. 그래서 어셈블리에 `org 0x7c00`.

## 4. 어셈블리 — 처음엔 딱 이만큼
부트 초기에는 C도 못 쓰는 "맨바닥(bare-metal)" 상태라 어셈블리가 필요하다.

| 개념 | 의미 | 비유 |
|------|------|------|
| **레지스터** (ax, bx…) | CPU 안의 초고속 임시 저장칸 (몇 개 안 됨) | 손에 든 도구 |
| **mov** | 값 옮기기 `mov ax, 5` | 대입(=) |
| **int** | 인터럽트 호출 (BIOS 기능 요청) | 함수 호출 |
| **jmp** | 다른 코드로 점프 | goto |

- **리얼 모드 → 보호 모드(Protected Mode)**: 처음엔 CPU가 옛날 16비트 호환 모드로 켜지고, 32비트 기능을 다 쓰려면 모드를 전환해줘야 한다. (지금은 이 정도만)

---

## 정리: 개념이 연결되는 그림
```
부팅(③④) → 코드가 메모리에 올라감(①②)
          → C 포인터로 화면 주소 0xB8000에 글자 씀(②)
          → 어셈블리로 BIOS에게 일 시킴(④)
```
이 4개가 손에 잡히면 OSDev "Bare Bones" 코드가 외계어로 보이지 않는다.

## 앞으로의 로드맵
```
Hello World 출력
  → GDT/IDT 설정 (메모리·인터럽트 기초)
  → 키보드 입력 받기
  → 메모리 관리 (페이징)
  → 멀티태스킹 (프로세스/스케줄러)
  → 파일 시스템
```

### 개발 환경 (다음 단계)
- **에뮬레이터**: QEMU (재부팅 1초, 디버깅 쉬움 — VirtualBox보다 OS개발에 적합)
- **크로스 컴파일러**: `i686-elf-gcc` (Windows용이 아닌 맨바닥 코드 생성)
- **어셈블러**: NASM
- **빌드**: `ld`, `make`
- **Windows에서 권장 셋업**: WSL2(Ubuntu) 안에서 작업 → OSDev 표준 환경과 거의 동일

## 잘 헷갈리는 점
- 호스트(Windows)용 GCC로 컴파일하면 안 된다 → **크로스 컴파일러**로 맨바닥 바이너리를 만들어야 함.
- 부트로더(512B)와 커널은 별개. BIOS는 부트로더만 불러오고, 부트로더가 커널을 마저 로드.
- `0xB8000`(VGA 출력)은 보호 모드 진입 후/텍스트 모드에서 동작 — 모드와 상황에 따라 방법이 다름.
