## 한 줄 요약
포르잔 두 교재는 **C++98/03 시대 사고**가 뼈대다. 실무·면접·최신 코드베이스는 **C++11 이후(모던 C++)** 를 전제로 한다. 이 부록은 두 트랙을 다 본 뒤 반드시 갱신해야 할 차이를 모은다. 핵심 표어: **"new/delete를 직접 쓰지 마라, RAII와 스마트 포인터에 맡겨라."**

---

## A. 스마트 포인터 — `new/delete`의 은퇴
교재의 수동 `new`/`delete`(→ [[OOP Ch09 참조·포인터·메모리 관리]], [[SA Ch09 포인터]])는 누수·이중 해제의 원천. 모던 C++은 소유권을 타입으로 표현한다.
```cpp
#include <memory>
auto p = std::make_unique<int>(42);   // 단독 소유, 자동 해제
auto s = std::make_shared<Node>();    // 공유 소유(참조 카운트)
// delete 불필요 — 스코프를 벗어나면 자동 소멸
```
- `unique_ptr`: 소유자 하나, 복사 불가·이동 가능. **기본 선택지.**
- `shared_ptr`: 여러 소유자, 마지막이 사라질 때 해제. 순환 참조는 `weak_ptr`로 끊는다.
- 원시 포인터는 "소유하지 않는 관찰자"로만 사용.

## B. RAII — 자원은 객체 수명에 묶는다
- **RAII**(Resource Acquisition Is Initialization): 생성자에서 자원 획득, 소멸자에서 해제 → 예외가 나도 누수 없음.
- 표준 라이브러리가 이미 RAII: `std::vector`, `std::string`, `std::fstream`, `std::lock_guard`.
- 직접 `delete`/`fclose`/`unlock`을 호출하고 있다면 보통 설계가 틀린 것.
- → [[OOP Ch14 예외 처리]]의 "예외 안전성"과 직결.

## C. Rule of Three → Rule of Five → Rule of Zero
교재의 **Rule of Three**(소멸자·복사 생성자·복사 대입)에 **이동(move)** 이 추가된다.
```cpp
class Buffer {
public:
    Buffer(Buffer&&) noexcept;             // 이동 생성자
    Buffer& operator=(Buffer&&) noexcept;  // 이동 대입
};
```
- **Rule of Five**: 위 다섯을 함께 고려.
- **Rule of Zero**(권장): 자원을 스마트 포인터/컨테이너에 맡기면 다섯 개를 **하나도 안 써도 된다.**

## D. `auto` · 범위 기반 for · 균일 초기화
```cpp
auto n = 42;                     // 타입 추론
std::vector<int> v {1, 2, 3};    // 중괄호 초기화
for (auto x : v) std::cout << x; // range-based for
for (auto& x : v) x *= 2;        // 참조로 원본 수정
```

## E. 람다와 `std::function`
- 익명 함수로 콜백·전략·알고리즘 인자를 간결하게.
```cpp
auto sq = [](int x){ return x * x; };
std::sort(v.begin(), v.end(), [](int a, int b){ return a > b; });
```
- → [[OOP Ch20 디자인 패턴]]의 전략(Strategy)을 가상함수 대신 람다로 대체.

## F. 이동 의미론 (move semantics)
- `std::move`는 "이 자원을 가져가도 된다"는 표시. 복사 대신 **소유권 이전** → 큰 객체 반환·전달 비용 제거.
```cpp
std::string make();
std::string s = make();   // 반환값은 이동(또는 RVO로 복사 생략)
```

## G. 그 밖에 알아둘 키워드
| 기능 | 의미 | 도입 |
|---|---|---|
| `nullptr` | 타입 안전한 널 포인터 | C++11 |
| `override` / `final` | 가상함수 재정의 검증 | C++11 |
| `constexpr` | 컴파일 타임 상수/계산 | C++11/14 |
| `std::string_view` | 복사 없는 문자열 참조 | C++17 |
| `std::optional` | "값이 없을 수도" 표현 | C++17 |
| 구조적 바인딩 `auto [a,b]` | 묶음 분해 | C++17 |
| 개념(concepts) | 템플릿 제약 | C++20 |

→ 템플릿/제네릭은 [[OOP Ch15 제네릭 프로그래밍 — 템플릿]], 컨테이너·알고리즘은 [[OOP Ch19 표준 템플릿 라이브러리 — STL]] 참고.

## 교재 → 모던 전환 체크리스트
- [ ] `new`/`delete`를 `make_unique`/`make_shared`로 바꿨는가
- [ ] 자원 관리 클래스에 이동 연산을 고려했는가(또는 Rule of Zero로 회피)
- [ ] 반복문을 range-based for로 단순화했는가
- [ ] 함수 포인터/함수 객체를 람다로 대체할 수 있는가
- [ ] 문자열 읽기 전용 인자를 `const std::string&` 또는 `string_view`로 받는가
