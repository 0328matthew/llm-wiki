## 한 줄 요약
컴퓨터는 **하드웨어 + 소프트웨어**로 동작하고, 프로그래밍은 **문제 → 알고리즘 → 코딩 → 테스트**의 단계를 거친다. 이 책의 출발점은 OOP가 아니라 **구조적·절차적 사고**: 큰 문제를 작은 단계로 쪼개 순서대로 푸는 알고리즘이 중심이다.

---

## 1.1 컴퓨터 하드웨어와 소프트웨어
- **하드웨어**: CPU(연산·제어 장치), 주기억장치(RAM), 보조기억장치(디스크), 입출력장치
- **소프트웨어**: 시스템 소프트웨어(OS·컴파일러)와 응용 소프트웨어(워드·게임 등)
- 폰 노이만 구조: 프로그램과 데이터가 같은 메모리에 저장되고 명령어를 **순차적으로** 인출·실행 → 절차적 사고의 물리적 근거

## 1.2 컴퓨팅 환경
- **개인 컴퓨팅**: 단독 PC에서 모든 처리
- **시분할 / 클라이언트–서버**: 중앙 컴퓨터를 여러 사용자가 공유 / 요청–응답 분담
- **분산 컴퓨팅**: 네트워크로 연결된 여러 컴퓨터가 협력
- 환경이 달라도 프로그램 작성의 본질(알고리즘 → 코드)은 동일하다

## 1.3 컴퓨터 언어의 계층
1. **기계어(machine language)** — 0/1, CPU가 직접 실행. 이식성 없음
2. **어셈블리어** — 기계어에 기호(mnemonic) 부여, 어셈블러가 번역
3. **고급 언어(high-level)** — 사람 친화적, 이식성 ↑ (C++, C …)

C++ 빌드 파이프라인:
```
소스(.cpp) → [전처리기] → [컴파일러] → 목적파일(.o) → [링커] → 실행파일
```
- **전처리기**: `#include`, `#define` 지시문 처리
- **컴파일러**: 문법 검사 + 목적코드 생성
- **링커**: 여러 목적파일·라이브러리 결합

## 1.4 프로그램 개발 과정 (구조적 핵심)
1. **문제 이해·분석** — 입력·출력·처리 명확히
2. **알고리즘 설계** — 의사코드 / 순서도로 단계 표현
3. **코딩** — 알고리즘을 C++ 문장으로 옮김
4. **컴파일·디버깅** — 문법·논리 오류 제거
5. **테스트** — 다양한 입력으로 검증
6. **유지보수** — 수정·확장

> 핵심: 코딩 전에 **알고리즘을 먼저 설계**한다. 키보드부터 두드리지 않는다.

## 1.5 구조적 프로그래밍 철학
- **하향식(top-down) 분해**: 큰 문제 → 부분 문제 → 더 작은 단계로 쪼개기
- **세 가지 제어 구조만으로 모든 알고리즘 표현 가능**: 순차(sequence), 선택(selection), 반복(iteration)
- **goto 지양**: 흐름이 위→아래로 읽히는 구조 유지 → 가독성·검증성 ↑
- 소프트웨어 공학: 정확성·유지보수성·재사용성을 위한 규율

## 1.6 알고리즘 표현 — 순서도와 의사코드
- **순서도(flowchart)**: 기호로 흐름 표현 (타원=시작/끝, 평행사변형=입출력, 사각형=처리, 마름모=판단)
- **의사코드(pseudocode)**: 자연어 + 약식 구조로 알고리즘 기술 → 언어 독립적

의사코드 예 — 두 수의 평균:
```
read num1, num2
set avg = (num1 + num2) / 2
print avg
```

## 자주 하는 실수
- 알고리즘 설계 없이 곧장 코딩 → 논리 구조가 엉킴
- 컴파일 오류(빌드 단계)와 실행 오류(런타임)를 구분 못 함
- 링커 오류(`undefined reference`)를 문법 오류로 오해 — 정의 누락/라이브러리 미연결
- "고급 언어니까 컴파일 불필요"라고 착각 → C++는 반드시 컴파일 단계 필요
