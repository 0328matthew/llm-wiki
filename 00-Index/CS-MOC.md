## 두 트랙 대응표 — 같은 주제, 다른 순서
같은 개념을 두 책이 어디서 다루는지. **OOP 트랙은 클래스를 일찍**, **구조적 트랙은 절차적 기초를 먼저** 깐다.

| 주제 | 객체지향 (OOP) | 구조적 (SA) |
|---|---|---|
| 입문·언어 기초 | Ch01–02 | Ch01–02 |
| 표현식·문장 | Ch03 | Ch03 |
| 선택 | Ch04 | Ch05 |
| 반복 | Ch05 | Ch06 |
| 함수 | Ch06 | Ch04 |
| 입출력·파일 | Ch16 | Ch07 |
| 배열 | Ch08 | Ch08 |
| 포인터·메모리 | Ch09 | Ch09 |
| 문자열 | Ch10 | Ch10 |
| 열거형·구조체·공용체 | (Ch07 일부) | Ch11 |
| 클래스 | Ch07 | Ch12 |
| 클래스 고급(static/friend/연산자) | Ch13 | Ch13 |
| 상속·클래스 관계 | Ch11 | Ch14 |
| 다형성 | Ch12 | Ch14 일부 |
| 예외·템플릿·STL·패턴 | Ch14–20 | (없음 → OOP 트랙으로) |

> 학습 경로 추천: C/절차지향이 처음이면 **SA Ch01→14**로 기초를 다진 뒤, **OOP Ch11→20**으로 객체지향 심화. 이미 절차적 프로그래밍을 안다면 **OOP 트랙 단독**으로 충분.

## 왜 이걸 LLM 위키에 두는가?
- **코드 리터러시** → LLM이 생성한 C++ 코드를 읽고 검증하려면 언어 모델(model)이 아니라 *프로그래밍 모델*을 알아야 함 → [[Tool Use]]
- **메모리·포인터 직관** → LLM은 메모리 안전성 버그(누수·dangling·overflow)에 약함 → 사람이 잡아야 할 지점
- **자료구조/STL** → 알고리즘·성능 사고는 [[Math-MOC|수치해석]]·시뮬레이션과 직결
- **OOP 설계 사고** → 디자인 패턴은 에이전트/툴 아키텍처 설계에도 전이됨 → [[Agent란 무엇인가]]
